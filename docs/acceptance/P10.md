- Код: `41e8968` (тег `p10`).
- `.136` — Windows 10 19045.7846, CSP 5.0.13003, `WORKSTATION-1`.
- `.137` — Windows 10 19045.7807, CSP 4.0.9963, `WORKSTATION-2`.

## Ограничения и честные границы

- Потеря ответа проверена **детерминированным HTTPS-прокси** (тестовый
  инструмент `cmd/acceptance proxy`), который принял запрос backend и
  отбросил первый ответ; это не физический обрыв кабеля.
- Заполнение диска выполнено на отдельном 16 MB VHD, назначенном только
  каталогу состояния агента; системный диск не заполнялся.
- Занятый профиль имитировался загрузкой его hive; отдельный race «вход
  пользователя ровно между проверкой и LoadHive» не воспроизводился
  детерминированно, но используется тот же sharing violation path.
- Выключение VM для краша не применялось: для внезапного завершения
  использовался процесс агента/службы и рестарты.
- P11–P12 (нагрузка 200+) не входят в этот протокол.

## Очистка

- Временные GPO/OU/share, профиль-заглушка, VHD, тестовые папки,
  `corrupt-*` очередь, hosts-запись, firewall rule и acceptance-proxy task
  удалены.
- Финальные агенты установлены на обеих станциях, служба LocalSystem
  работает; `agent-config.json` (GPO-managed) сохранён.
- SQL-история и записи отказов оставлены для аудита; персональные
  сертификаты и приватные ключи не извлекались.
