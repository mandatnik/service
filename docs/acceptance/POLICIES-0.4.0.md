# Приёмка уточнений 0.4.0 — 14.11.2026

Проверены группы машин, назначаемые политики папок, ограничения `.cer`
и компактное представление сертификатов/лицензий. Спецификация:
[folder-policies.md](../folder-policies.md).

## Среда и результат

- Реальный SQL Server 2019 на `192.168.189.138`, БД `Mandatnik`.
- Бэкенд portable EXE, административный HTTPS `:8444`, агентский HTTPS `:8443`.
- `.136`: LocalSystem-служба, CSP 5.0.13003, клиентская лицензия.
- `.137`: LocalSystem-служба, CSP 4.0.9963, серверная лицензия.
- Обе службы обновлены MSI 0.3.0 → 0.4.0; UUID и зашифрованные DPAPI-файлы
  сохранились. Сравнивались SHA-256 файлов до/после, не содержимое ключей.
- Go unit tests, `go vet`, Windows amd64 CGO=0 сборки и Vite production build прошли.

Браузерная проверка выполнялась на локальном временном HTTP-просмотре того же
embedded-бандла и API с реальной БД: браузер не доверяет стендовому TLS-УЦ.
TLS-предупреждение не обходилось. Реальные HTTPS API, агенты и SQL TLS отдельно
проверялись с доверенным корнем стенда, без отключения проверки сертификатов.
Временный просмотр остановлен после проверки; HTTP-слушатель в продукт не добавлен.

Опрос не ускорялся в коде: ручные задания создавались через API, затем службы
перезапускались для немедленного штатного register/sync. Доставка отчёта
выполнялась обычной очередью агента. Тестовые политики, группа и файлы убраны
после снятия назначений; финальные службы работают без тестовых назначений.

```sh
go test ./...
go vet ./...
MANDATNIK_POLICY_TEST_CONFIG="$PWD/.secrets/acceptance.json" \
  go test ./internal/backend/store -run TestPoliciesSQLServer -v

go run ./cmd/acceptance contract -config .secrets/acceptance.json \
  -evidence evidence/policies-0.4.0/contract
```

Для повторения реального файлового сценария используется
`tools/stand/test-folder-policies.py`: prepare → сбор → check → reinclusion →
сбор → check → revoke → сбор → check → cleanup. Перед prepare разместить пять
тестовых файлов в выделенной `C:/ProgramData/Mandatnik/policy-acceptance/`:
keep/a.cer, trash/b.CER, other/c.cer, keep/ignored.crt, keep/ignored.pem.
Используйте разные публичные сертификаты. После каждого сбора дождаться приёма
отчёта сервером (агент отправляет очередь через свой интервал доставки).
На macOS стендовый УЦ проверялся `/usr/bin/python3`; Python 3.15 включает
дополнительную строгую проверку AKI, которого нет в прежнем стендовом УЦ.
Пароли остаются в `.secrets/`, в доказательства не записываются.
