## Repair

Финальный MSI установлен из доступного deployment share. На `.136`
выполнен:

```text
msiexec /f {64E20BF5-DDF6-4704-9374-E175CA30152F} /qn /norestart
```

Результат: exit 0, служба Running, `identity.dpapi` на месте. Repair
использует MSI source (нормальное поведение Windows Installer); при
недоступном share repair завершается 1603, что задокументировано как
эксплуатационное требование сохранять source для repair.

## Uninstall

- Текущая политика: `telehack-agent.exe uninstall` (без `-purge`) и
  стандартный MSI `/x` удаляют продукт и службу, но сохраняют
  `AgentDir` (identity/DPAPI/encryption ring/journal/queue/logs), поэтому
  повторная установка продолжает ту же машину. Полная очистка — только
  `telehack-agent.exe uninstall -purge`; GPO-конфиг не удаляется.
- Историческая запись прогона P09: `.136` CLI `uninstall` удалил `AgentDir`
  и вызвал MSI `/x`; `.137` стандартный MSI `/x` очистил состояние. Это
  поведение изменено после P09; повторная установка теперь требует явного
  `-purge`, иначе identity сохраняется.
- После переустановки с `-purge` создаётся новая identity; при совпадении
  hostname создаётся заявка «Ожидает подтверждения», администратор выбирает
  замену установки или отдельную машину. Автоматического присоединения к
  старой карточке нет. История старой машины сохранена.

## Неверное обновление

На `.136` подан повреждённый MSI: `msiexec /i bad-update.msi /qn
/norestart` → exit `1620`; служба продолжила работать, identity/DPAPI не
изменились, состояние не потеряно.
