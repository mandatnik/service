# Группы машин и политики папок (0.4.0)

Группа содержит рабочие машины, машина может состоять в нескольких группах.
В таблице «Машины» флажки выбирают отдельные строки или текущую страницу.
Выбор сохраняется при переходе между страницами и фильтрами; счётчик показывает
полный выбор. «Добавить» добавляет выбранные машины в существующую или новую
группу, сохраняя прежнее членство. Раздел «Группы машин» позволяет переименовать
группу, изменить её состав и удалить группу без удаления самих машин.

Политика — название и один многострочный текст правил, назначенный любому
числу машин и/или групп. Без назначенных политик папки не сканируются;
личные хранилища продолжают обследоваться. Общего списка папок для всех машин нет.

```
C:/Users/*/AppData/testDir/
!C:/Users/*/AppData/testDir/trashFolder
C:/ProgramData/
```

Это текст, не YAML. Используется синтаксис шаблонов, похожий на `.gitignore`,
с **положительными включениями**: путь включает папку с содержимым, `!` исключает.
Поддержаны `*` (часть имени без `/`), `?` (один символ без `/`), `**` (уровни
папок), `[abc]`, `[a-z]`, `[!abc]`, пустые строки и комментарии с `#` в начале
строки. Путь абсолютный; `/` и `\` нормализуются, сравнение Windows-путей без
учёта регистра. Пробелы по краям строк удаляются, внутри пути сохраняются.
Переход `..` запрещён. Завершающий `/` необязателен: правило соответствует
папке и всему её поддереву, но не папке с похожим префиксом имени.
Произвольные конструкции `.gitignore` вне перечисленного синтаксиса не заявлены.

Внутри политики действует последнее совпавшее правило. Можно сохранить
политику только с исключениями. Папки обходятся рекурсивно; переходы по
символическим ссылкам не выполняются. Сканируются только `.cer` (в том числе
`.CER`), в DER или PEM-кодировке. `.crt` и `.pem` игнорируются независимо от содержимого.

## Объединение

1. Политики одного уровня независимы, результаты их включений объединяются.
2. Для файла, найденного **групповой** политикой, дополнительно проверяются
   исключения каждой политики, назначенной **напрямую машине**.
3. Если другая прямая политика включает этот файл, он остаётся в результате:
   исключения прямых политик не отменяют включения других прямых политик.
4. Одна политика, полученная через несколько групп, вычисляется один раз.
   Если она назначена также напрямую, применяется на уровне машины.
5. Один путь и один сертификат не дублируются при пересечении политик.

Пример: группа включает `C:/Certs/`, а машина исключает `!C:/Certs/trash/`.
Файлы `trash` от группы не собираются. Другая групповая политика не обходит
прямое исключение. Отдельная прямая политика `C:/Certs/trash/` включает их снова.

## Хранение и синхронизация

Миграция `0003_folder_policies.sql` создаёт `machine_groups`,
`machine_group_members`, `folder_policies`, `folder_policy_machines`,
`folder_policy_groups`. Прежние глобальные папки, если они заданы, превращаются
в политику «Ранее настроенные папки», назначенную существующим машинам.
Новые машины её автоматически не получают. Старый JSON настроек сохраняется
для проверки его JCS-хеша; поле `cert_directories` никогда не передаётся
агенту с содержимым и больше не принимается при сохранении глобальных настроек.

Бэкенд вычисляет эффективные `folder_policies` для конкретной машины при
регистрации, переименовании и каждом sync. Хеш включает ID, название, правила
и уровень назначения. Изменение состава группы или назначений меняет хеш,
даже если версия общих настроек не изменилась. Агент получает конфигурацию
при штатном 10-минутном опросе; сбор — по расписанию или ручному заданию.
Для немедленной проверки создайте ручное задание в карточке машины.

Результат папок — стабильный источник `folder/folder-policies`. Его полный
успешный пустой результат, в том числе после снятия всех назначений, прекращает
активность прежних файловых наблюдений, сохраняя историю. Частичная ошибка,
отмена или превышение лимита не удаляют наблюдения. Устаревший отчёт старого
агента не восстанавливает файлы после более нового полного сканирования политик.
Лимит `max_files` применяется к уникальным подходящим `.cer` за весь обход.

Обновление требует согласованной установки бэкенда и агентов 0.4.0: старый
агент отклоняет неизвестное поле `folder_policies`. MSI сохраняет UUID, DPAPI,
очередь и настройки. Перед переключением бэкенда остановите старые агенты,
затем обновите MSI и возобновите службы. Откат старых бинарников после приёма
нового формата требует также восстановления соответствующего состояния агента.

## Административный API

Все методы под `/api/admin/v1`, с существующей сессией; записи требуют CSRF.

| Метод | Путь | Тело/результат |
|---|---|---|
| GET | `/inventory-settings` | `machines:[{id,name}]`, `groups`, `policies` с назначениями |
| POST | `/groups` | `{name,machine_ids:[]}` → `{id}` |
| PUT | `/groups/{id}` | `{name,machine_ids:[]}`: заменить название/состав |
| POST | `/groups/{id}/members` | `{machine_ids:[]}`: идемпотентно добавить, не заменить |
| DELETE | `/groups/{id}` | Удалить группу, её членство и назначения политик группе |
| POST | `/folder-policies` | `{name,rules,machine_ids:[],group_ids:[]}` → `{id}` |
| PUT | `/folder-policies/{id}` | Заменить название, правила и назначения |
| DELETE | `/folder-policies/{id}` | Удалить политику и назначения |

Изменения транзакционные; несуществующая цель откатывает весь запрос.
Дубли названий дают 409, неверные правила/назначения — 400, отсутствующая
редактируемая сущность — 404. Изменения записываются в события администратора.

## Отображение сертификатов и лицензий

Таблица показывает жирный CN владельца, ниже OU и O. Атрибуты извлекаются
по OID из сохранённого DER, а не разрезанием строки DN по запятым.
Полные DN, ИНН, СНИЛС и отпечаток доступны в карточке.
Встроенная лицензия: зелёный «Есть», серый «Нет»; если разбор не удался —
«Не определено», без ложного утверждения об отсутствии.

В таблице лицензий — машина, версия CSP/ядра, клиентская/серверная лицензия,
состояние, дата и пробность русскими подписями. Исходный код, источник API,
основа времени и ошибки раскрываются по нажатию на строку.
