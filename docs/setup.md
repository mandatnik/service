# Первоначальная настройка Windows-бэкенда (интерактивный мастер)

`mandatnik-backend setup` — интерактивный консольный мастер первоначальной
настройки (Windows, консоль «от имени администратора»). `configure` —
изменение настроек завершённой установки. Обычный `run` без завершённой
настройки сообщит, что нужно выполнить `setup`, и завершится; мастер при
старте службы не запускается.

## Команды

```
mandatnik-backend.exe setup [--adopt]
mandatnik-backend.exe configure
mandatnik-backend.exe admin-reset-password [-email EMAIL]
mandatnik-backend.exe service-install|service-uninstall|service-start|service-stop|service-status
```

Все подсказки — на русском. Пароли вводятся скрыто и никогда не передаются
аргументами командной строки. Перед применением показывается сводка без
секретов с подтверждением.

## Жизненный цикл и совместимость

- Черновик и статус шагов хранятся в `Backend\setup\` (`draft.json`,
  DPAPI-защищённые `draft-secrets.bin`); прерванный `setup` предлагает
  продолжить или явно удалить черновик.
- Маркер завершённой установки — `Backend\setup\install-state.json`; он
  выставляется только после успешного запуска службы и её проверки.
- Повторный `setup` завершённой установки не пересоздаёт данные — направляет
  в `configure`.
- Существующие установки без маркера продолжают работать как раньше
  (совместимость); записать маркер без пересоздания данных: `setup --adopt`
  (проверяет конфигурацию, TLS-файлы и подключение к БД).

## Шаги мастера

1. Схема адресов: простой (один домен/сертификат) или расширенный (отдельные
   адреса и сертификаты для агентского API `:8443`, админки `:8444`,
   интеграционного API `:8446`). Порты проверяются на конфликты и возможность
   открыть. Различаются адрес прослушивания и клиентские адреса (DNS/IP).
2. Сертификаты: импорт PFX/PEM, CSR для УЦ Windows (с ожиданием и приёмом
   сертификата), собственный CA установки (экспорт публичного CA и
   зашифрованного ключа, удаление рабочей копии ключа после явного
   подтверждения). Проверки: SAN (CN не учитывается), срок действия, KeyUsage,
   EKU ServerAuth, соответствие ключа, цепочка, алгоритмы TLS-стека. Если
   доверие не проверено — это сообщается явно; недоступность проверки отзыва
   отличается от подтверждённого отзыва.
3. SQL Server: подключение к уже созданной БД (без sa, без создания БД).
   TLS включён по умолчанию; отключение шифрования — только после явного
   предупреждения и подтверждения (сервер, принудительно требующий TLS,
   отклонит такое подключение). БД классифицируется: пустая — новая установка;
   таблицы «Мандатника» — отказ (нужен `--adopt` или восстановление);
   чужая непустая — отказ. Права на миграции проверяются, затем применяются
   миграции (уже применённые не откатываются — это фиксируется явно).
4. Учётная запись службы: новая локальная со случайным паролем (создаётся
   через `net user` с паролем через stdin, право SeServiceLogonRight) или
   существующая локальная.
5. Первый суперадминистратор: имя, email, пароль ×2 (bcrypt ≥12 символов).
6. Применение: конфигурация `backend.json` (без секретов), пароль БД —
   DPAPI-machine файл `db-password.bin` (config распознаёт префикс
   `MNDKDPAPI1`), keyring/HMAC-ключи лицензий (не перезаписываются),
   регистрация службы с автозапуском, запуск, проверка TLS-интерфейсов и БД.
7. Комплект восстановления `Backend\setup\recovery.mndk`: пароль + AES-256-GCM
   + scrypt; состав: backend.json, keyring, HMAC-ключ, TLS-материал, CA (если
   есть), пароль БД. Пароль службы НЕ включается. Проверяется чтение после
   экспорта. Резервная копия БД — отдельно; после ротации ключей комплект
   обновить.
8. Памятка: адреса интерфейсов, служба, какие порты открывать (Агентский API —
   сеть АРМ; Админка — админ-подсеть; Интеграционный API — доверенные системы;
   исходящий порт SQL Server), расположение настроек/секретов/журналов,
   команды `configure` и `admin-reset-password`.

## configure

Разделы: адреса/порты, сертификаты, БД, учётная запись службы. Изменения
проверяются, текущая конфигурация сохраняется в `Backend\setup\config-backups\`,
служба перезапускается и проверяется; при неудаче возвращается предыдущая
конфигурация. Новая БД, суперадминистратор или ключи шифрования не создаются;
подмена подключения на чужую установку блокируется.

## admin-reset-password

Требует прав администратора; задаёт новый пароль выбранному суперадминистратору
(список выводится при неоднозначности), завершает его сессии, пишет запись
аудита без секретов; старый пароль/хеш не показываются.

## Файлы

```
Backend\setup\install-state.json   — маркер завершённой установки
Backend\setup\draft.json           — черновик (без секретов)
Backend\setup\draft-secrets.bin    — DPAPI-секреты черновика (текущий пользователь)
Backend\setup\runtime-secrets.bin  — DPAPI-machine секреты (служба читает после перезагрузки)
Backend\db-password.bin            — DPAPI-machine пароль БД (acl: админ+SYSTEM+служба)
Backend\setup\recovery.mndk        — комплект восстановления
```
