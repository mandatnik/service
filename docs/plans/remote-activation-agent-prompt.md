# Промпт для агента реализации

Ниже готовое задание. Начальная точка — существующий checkout telehack2026.
Основная спецификация: [remote-activation-and-tasks.md](remote-activation-and-tasks.md).

---

Ты реализуешь в существующем проекте telehack2026 единую систему задач
и удалённую установку лицензий КриптоПро с пулами ключей.

Сначала прочитай `docs/plans/remote-activation-and-tasks.md` полностью.
Это основной документ согласованных требований. Также прочитай применимые
AGENTS.md, README.md, ARCHITECTURE.md, IMPLEMENTATION_PLAN.md, docs/protocol.md,
docs/configuration.md, docs/folder-policies.md, api/openapi.yaml и
`docs/research-license-activation.md`. Проверь текущую ветку, diff и фактический код.
В рабочей копии могут быть чужие незакоммиченные изменения: сохраняй их,
не выполняй reset/clean и не заменяй файлы старыми версиями.

Это поручение на реализацию, а не на повторное проектирование.
Технические детали, не меняющие согласованное поведение, решай самостоятельно.
Существенное противоречие с кодом сначала исследуй; не упрощай требования молча.
Нельзя выдавать отсутствие CAdES, RSA или метаданных провайдера за подтверждённый
успех или отсутствие необходимости лицензии. Не оставляй критические TODO вместо
работающих серверной и агентской частей.

## Ожидаемый результат

1. Раздел «Пулы лицензий»: создание/архивирование, CSP 4/5, client/server,
   заявленный срок 1 год/2 года/бессрочно, ручной ввод и массовая вставка номеров,
   глобальная дедупликация, маски, состояния и история закреплений.
2. Общая задача и отдельные выполнения на РС: scan и install_license,
   назначение из выбранных РС/групп без дубликатов, снимок получателей,
   списки/детали/журнал задач, отмена и read-only согласование неизвестного результата.
3. «Активировать лицензию» рядом с «Добавить в группу». Модалка с одним пулом
   и четырьмя категориями из спецификации. Select-all второго списка;
   действующие приобретённые лицензии disabled, их ID не входят в финальный POST;
   в первом списке без действующей лицензии checkbox включён по умолчанию,
   с действующим триалом — снят, но enabled для ручного включения;
   неизвестные состояния требуют проверки. Несовместимые РС исключены с причиной.
   При дефиците ключей админ явно уменьшает получателей, сервер не выбирает их сам.
4. Атомарное резервирование ключей, идемпотентное создание задач и согласованные
   переходы состояний даже при конкурентных запросах, потере ACK и рестартах.
5. Настройки сервера: poll_interval_seconds=60 (10–3600),
   inventory_freshness_seconds=86400, task_ttl_seconds=604800.
   Все возвращаются новым агентам и участвуют в config_hash. Плановый суточный
   сбор остаётся отдельной настройкой.
6. Агентские ключи шифрования, зашифрованные параметры каждого выполнения,
   нативная установка номера без окон и без участия пользователя, проверки
   результата, сохранение журнала попыток и безопасное восстановление.
7. Локальные логи агента, серверный аудит и UI с понятными причинами ошибок;
   никаких открытых номеров/секретных параметров в логах и ответах.

## Неподлежащие упрощению условия

- Задача установки использует один выбранный пул. Не заменяй версию, срок или
  client/server автоматически. Однозначно несовместимые РС не получают номер.
- Рекомендация основана на действующем по датам сертификате личного хранилища
  с реальной привязкой к провайдеру КриптоПро и без встроенной лицензии.
  RSA обязательно поддерживается: кейсодержатели будут тестировать RSA в КриптоПро.
  Алгоритм/issuer/подстрока имени не заменяют атрибуцию провайдера.
- Метаданные провайдера хранятся у наблюдения/привязки, не у общего DER.
  Публичные .cer из папок не считаются подтверждёнными CryptoPro-сертификатами.
  Реализуй чтение для существующих loaded/offline/file-store путей.
- Наличие закрытого ключа пока не проверяй. Заложи отдельное состояние not_checked
  и расширяемое правило; не выдавай наличие provider binding за доступность ключа.
- Неизвестность/устаревший или неполный личный сбор → четвёртый список.
  Отсутствующие метаданные могут требовать диагностики после повторного scan.
- Действующую приобретённую другую лицензию не заменяй даже при обходе UI или
  изменении состояния между preview и выполнением. Действующий подтверждённый
  триал можно заменить только после ручного выбора его строки и разрешения
  allow_trial_replacement в зашифрованных параметрах. Неизвестная пробность →
  четвёртый список, не разрешение записи. Триал не исключает РС из первого списка
  при наличии подходящего сертификата; его checkbox снят по умолчанию, но enabled.
  Для РС без действующей лицензии checkbox первого списка включён по умолчанию.
  Уже установленный назначенный номер сначала распознавай как успех без записи.
- Повторы разрешены только для того же ключа на той же РС: максимум 3 попытки,
  паузы 30 и 120 секунд, перед каждым повтором сначала read-only проверка.
  Счётчик persist до изменения. Сеть/ACK не являются новой попыткой установки.
  Определённо неверный номер не повторяй; generic HRESULT без контекста не считай
  достаточной классификацией неверного номера.
- После возможного изменения ключ не освобождай по таймеру/отмене/переустановке.
  При неясном результате удерживай назначение. Состояние outcome_unknown
  допускает read-only согласование, не автоматическую выдачу другому адресату.
- Нужны start/claim и гонкобезопасная отмена. Доставленный ciphertext сам по себе
  не разрешает запись. Не обещай exactly-once для внешнего изменения и не считай
  canceled доказательством, что номер не был записан.
- Журнал установки/очередь результатов не зависят от двухместной очереди отчётов.
  Повреждённый журнал не сбрасывай в пустой с повторным выполнением.
- Polling должен продолжаться во время долгой работы. Убери старое 10-минутное
  ограничение для ручного scan и лишнее ожидание 30-секундного work tick.
- Номер в БД зашифрован AES-256-GCM; keyring и отдельный HMAC-ключ дедупликации
  вне БД под ACL. Сервер расшифровывает номер только для назначения.
- Параметры всех items, включая scan, зашифрованы отдельной RSA-3072 парой РС:
  RSA-OAEP-SHA256 + AES-256-GCM, AAD привязывает все поля адресата и задания.
  Существующую ECDSA-пару подписи не переиспользуй для шифрования.
  Обновление публичного ключа подтверждается существующей подписью агента.
- Ключи РС и секретный локальный журнал защищены DPAPI + ACL. Поддержи ротацию,
  rename, старые незавершённые конверты и отказ при неподтверждённой новой регистрации.
- В UI нет раскрытия полного номера и экспорта. Импорт принимает plaintext через
  проверяемый TLS, но ответы/ошибки/логи его не содержат. Не сохраняй HTTP body
  импорта в аудит. Для диагностики достаточно ID лицензии и безопасных кодов.
- Исправь нулевую OLE-дату бессрочной лицензии. На реальной CSP 5 GetExpireDate
  вернул 1899-12-30 при Client/Unlimited/IsValid=true. Не показывай её просроченной.
- История jobs и старые агенты должны пережить переход. Не добавляй новые поля
  в старый ответ без проверки DisallowUnknownFields и контрактной совместимости.

## Проверки

Выполни весь перечень раздела 16 основной спецификации. Особое внимание:

- Конкурентные SQL-тесты резерва и дефицита, идемпотентность, claim/cancel/expiry.
- Состояния задач и точные агрегаты; поздние/повторные/противоречивые события.
- Шифрование с негативными тестами адресата, ID, срока, тега, key_id и ротации.
- Проверка отсутствия полного тестового номера во всех логах, ответах и state files.
- Fault injection до/после intent/write/verify/ACK, рестарт, повреждённый журнал,
  три попытки и паузы с управляемыми часами, независимый polling.
- Provider metadata RSA/КриптоПро против RSA/Microsoft, offline profiles,
  повторяющийся DER с разными bindings, unknown/no binding и future private-key rule.
- Windows-тесты на реальной SYSTEM-службе; нативный адаптер без PowerShell в продукте.
- Браузерная проверка пулов, модалки, disabled и select-all, дефицита, задач,
  причин ошибок, настроек и отсутствия секретов в UI/network responses.
- go test ./..., необходимые SQL/контрактные тесты, Windows cross-build
  agent/backend/acceptance, frontend build. Не ограничивайся только unit tests.

На стенде уже установлена оплаченная бессрочная лицензия WORKSTATION-1.
Не извлекай её в логи, не вводи заново, не меняй и не переноси на другую РС.
Положительный тест с новым действующим ключом возможен только после отдельного
его предоставления и разрешения. Отрицательные Windows-тесты выполняй на изолированной
РС/согласованном снимке без действующей лицензии, с восстановлением исходного
состояния и очисткой только собственных фикстур. Наличие SSH-доступа само по себе
не разрешает менять существующие лицензии или закрытые пользовательские ключи.

Если конкретный обязательный E2E недоступен, выполни остальные проверки и явно
зафиксируй этот пробел. Не называй его пройденным и не замещай реальный RSA-binding
только именем провайдера в mock. Не проси рабочий ключ ради обычных unit-тестов.
